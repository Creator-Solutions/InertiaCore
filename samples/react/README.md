# InertiaCore TypeScript sample

This project proves the declarations generated by `InertiaCore.TypeGen` compile under
`tsc --strict` and are usable from a typed React app.

The declarations in `types/inertia.generated.d.ts` are **generated** from the sample
`InertiaCoreTests.TestApp` assembly (do not edit by hand). CI regenerates them, runs
`tsc --noEmit`, and then verifies that renaming a props member in C# and regenerating
produces a compile error in the component that used the old name.

Regenerate locally (after building `InertiaCoreTests.TestApp`):

```bash
dotnet run --project InertiaCore.TypeGen/InertiaCore.TypeGen.csproj --framework net8.0 -c Debug -- \
  --assembly InertiaCoreTests.TestApp/bin/Debug/net10.0/InertiaCoreTests.TestApp.dll \
  --output samples/react/types/inertia.generated.d.ts \
  --emit-react-helper
```

The typed routes in `types/routes.ts` are generated from the committed route dump
(`InertiaCoreTests/Golden/routes.sample.json`), which mirrors the Development
`/_inertia/routes` endpoint:

```bash
dotnet run --project InertiaCore.TypeGen/InertiaCore.TypeGen.csproj --framework net8.0 -c Debug -- routes \
  --input InertiaCoreTests/Golden/routes.sample.json \
  --output samples/react/types/routes.ts
```

Type-check:

```bash
cd samples/react && npm ci && npx tsc --noEmit
```

What the sample shows:

- `app.tsx` — a typed page resolver: every name in `InertiaPageProps` must have a
  matching entry, and each component is bound to the props declared for that name.
- `Pages/*/Index.tsx` — page components typed with `InertiaPageProps['<Component>']`.
- `components/SharedBanner.tsx` — the generated `usePageProps` helper, whose result
  intersects page props with `InertiaSharedProps`.
- `routes-usage.ts` — the typed `route()` helper: known names and required parameters are
  enforced, and unknown names or missing parameters fail the type check.
